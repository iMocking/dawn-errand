## 2026-10-23（五）token 到期跳登录修复（前端自动续期 + TTL 治理）

- 问题：静止一段时间不操作，刷新页面即被踢到登录页。
- 根因审查结论：
  - 后端 access token 默认 TTL **900s（15 分钟）**（`config.go` `ACCESS_TOKEN_TTL` 默认 900；`REFRESH_TOKEN_TTL` 默认 1209600s=14 天）；
  - 后端续期接口 `POST /api/auth/refresh`（轮换 access+refresh）本就完整，登录响应含 `refresh_token`；
  - 前端断链：axios 401 拦截器直接清会话跳 /login，从不调用 refresh；`LoginResult` 无 refreshToken 字段，且**后端返回字段为 snake_case `refresh_token`，前端按 camelCase 读取导致首次登录把字面 "undefined" 写入 localStorage**（这是续期彻底失效的直接原因）。
- 修复（前端，`apps/admin`）：
  - `api/auth.ts`：`LoginResult` 增 `refreshToken`；新增 `refreshToken(refresh_token)` 调 `/auth/refresh`；登录/刷新响应经 `mapLoginResult` 把 `refresh_token` 映射为 `refreshToken`（消除 "undefined" 缺陷）；
  - `stores/auth.ts`：登录持久化 `admin_refresh_token`，`reset()` 一并清理；
  - `utils/request.ts`：401 拦截器改为「先静默 refresh（单飞，并发 401 只发一次）→ 更新本地 token/refresh_token/user/permissions → 重放原请求；refresh 失败才清会话跳登录」；`/auth/refresh` 与登录请求自身不递归。
- 后端：`config.go` 默认 TTL 保持 900s 未动（仅注释说明），**运行时以 `ACCESS_TOKEN_TTL=7200` 环境变量覆盖为 2 小时**（后端启动命令需携带该 env）。
- 验证（浏览器实测）：
  - 登录后 `admin_refresh_token` 长度 43（此前为 9 = "undefined"）✓；
  - 篡改 access token 模拟过期 → 刷新 → **停留原页面不跳登录**，access token 自动换新（JWT）、refresh 同步轮换 ✓；
  - access 与 refresh 同时失效 → 正确清会话跳 /login（预期安全边界）✓；
  - vue-tsc / eslint / vite build 全绿 ✓。
- 环境限制（本机 Application Control）：`C:\Apps\Go\pkg\tool\windows_amd64\link.exe` 自本轮起被策略拦截，`go build / go run / go test` 均无法重新链接；当前后端以 `.data\dawn-server-new.exe`（01:23 预编译，**缺实名认证接口路由**，实名相关接口 404）+ env TTL 7200 运行；集成测试（新凭据）已在拦截前全量 PASS（约 11s），拦截后无法重跑。恢复完整后端需用户放行 Go 工具链或提供其他 Go 安装后重新编译。
