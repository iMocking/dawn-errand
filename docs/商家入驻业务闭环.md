# 商家地推入驻业务闭环

> 适用：管理后台「新增商家」、业务员线下地推、平台审核、商家端登录经营。
> 目标：资料一次采集、审核可追溯、通过即具备真实经营权。

## 1. 角色

| 角色 | 职责 |
|---|---|
| 业务员（管理端 `merchant:create`） | 线下采集商家经营信息、证照、结算账户；提交/补件 |
| 审核员（`merchant:audit`） | 核对资料与证照、通过/驳回、查看开通账号 |
| 商家 | 审核通过后用手机号/邮箱 + 初始密码登录商家端，开店经营 |
| 平台 | 账号开通、密码重置、封禁/停用、审计留痕 |

## 2. 状态机

```
[业务员录入]
     │ POST /merchants
     ▼
  pending（待审核）
     ├── reject（必须填原因） ──► rejected（已驳回）
     │                               │ PUT /merchants/:id/application
     │                               └──► pending
     └── approve
           │ 1. 校验资料完整性
           │ 2. audit_status=approved, verified_at/by
           │ 3. 自动创建 merchant 用户 + credential + 双向绑定
           ▼
   approved + status=rest（休息中，账号可登录）
           │ 商家登录商家端 → 设置营业
           ▼
        open（营业中） ──封禁──► banned
```

关键约束：
- `pending/rejected` 不自动开通账号；只有 `approve` 才创建账号。
- 审核通过后默认 `rest`，避免无菜单/无营业准备时接单。
- 封禁由平台操作，商家端中间件直接拒绝。

## 3. 资料模型

### 3.1 商家主表（可检索/列表展示）
`name/category/contact/phone/address/address_sub/open_hours/delivery_range/commission/delivery_method/lat/lng/min_price/packing_fee/delivery_fee/auto_accept/announcement/service_phone`

### 3.2 `application_json`（资质/结算/账号，审核与留痕）
| 字段 | 说明 | 必填 |
|---|---|---|
| licenseNo / licenseImage | 营业执照号/照片 | 是 |
| legalName / legalIdCard | 法人姓名/身份证号 | 是 |
| idCardFront / idCardBack | 身份证正反面 | 是 |
| foodLicenseNo / foodLicenseImage | 食品经营许可证（餐饮） | 餐饮必填 |
| storefrontImages | 门头/店内照片（1-6 张） | 是 |
| bankName / bankAccountName / bankAccountNo | 结算账户 | 是 |
| accountPhone / accountEmail | 商家端登录账号 | 手机号默认同联系电话 |
| notes | 补充说明 | 否 |

### 3.3 认证与账号
- `audit_status/audit`、`reject_reason`、`submitted_at`、`verified_at`、`verified_by`。
- `owner_user_id` 绑定商家端用户；`users.role=merchant`、`users.merchant_id` 双向绑定。
- 初始密码只返回一次；数据库仅存 Argon2id 哈希。

## 4. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/merchants` | `merchant:create` | 完整入驻申请 |
| PUT | `/api/merchants/:id/application` | `merchant:create` | 驳回后补件重提 |
| POST | `/api/merchants/audit/:id` | `merchant:audit` | `approve` 返回账号；`reject` 必填原因 |
| POST | `/api/merchants/:id/account/reset` | `merchant:create` | 重置密码，旧会话失效 |
| POST | `/api/uploads` | 登录态 | 图片上传（multipart `file`） |
| GET | `/api/merchants/:id` | `merchant:detail` | 详情含认证/账号状态 |

## 5. 校验规则

- 名称/类型/联系人/电话/区域/地址/营业时间必填。
- 营业执照、法人身份证、身份证正反面、门头照、结算账户必填。
- 餐饮必须上传食品经营许可证。
- 佣金 0-100；金额不得为负。
- 驳回原因必填；补件后申请单号保留、状态回到 pending。
- 审核通过前商家端接口拒绝（未绑定或未通过审核）。

## 6. 账号交付与异常

| 场景 | 处理 |
|---|---|
| 手机号/邮箱已属其他角色 | 审核开通失败；业务员更换账号或走账号变更 |
| 初始密码遗失 | 商家详情「重置登录密码」，旧 token 立即失效 |
| 审核通过但账号开通失败 | 审核状态已通过，可在详情重新开通（当前接口 `POST /:id/account`） |
| 图片不清晰/资料不实 | 审核员驳回并填写原因，业务员补件重提 |
| 商家被封禁 | 商家端中间件返回 403，无法经营 |

## 7. 验收清单

- [x] 业务员可录入完整经营/资质/结算/账号资料并上传证照。
- [x] 审核通过自动创建商家端账号，返回一次性初始密码。
- [x] 商家用手机号/邮箱 + 初始密码登录，`/api/app/store/me` 可用。
- [x] 驳回必须填原因，补件后回到待审核。
- [x] 重置密码后旧会话失效。
- [x] 集成测试覆盖（43/43）与管理端 typecheck/build。
