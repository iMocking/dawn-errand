# 后端商用化完善计划（M0–M5）

> 目标：把 `dawn-errand` 后端从「平台运营后台 + 身份认证」升级为**可商用的本地即时配送交易平台**，支撑用户端 / 商家端 / 骑手端真实业务闭环。
> 依据：[后端能力审阅与联调准备](后端能力审阅与联调准备.md)、[三端联调接口契约](三端联调接口契约.md)
> 原则：**小步交付、每阶段可编译 / 可测试 / 可联调 / 可回滚**；后台 `/api/*` 契约零破坏。
> 版本：v1.0（2026-10-25）

---

## 1. 商用级定义（DoD）

一个能力算「商用级」，必须同时满足：

1. **业务闭环**：有创建、流转、终态、异常与补偿，不只读写单表。
2. **一致性**：跨聚合写操作在事务内；状态流转带旧状态条件（乐观并发）；关键写接口幂等。
3. **权限与隔离**：角色 + 主体绑定 + `tenant.Scope` 三层校验；越权返回明确错误码。
4. **可审计**：资金、状态、审核、账号变更全部落 `audit_logs` 或 `order_events`。
5. **可观测**：关键接口有日志（含 `request_id`）与指标（下单量、支付成功率、抢单冲突、履约时长）。
6. **可运维**：迁移可回滚；有 seed/联调数据；有冒烟脚本；故障可定位。
7. **可测试**：应用层单测 + HTTP 集成测试覆盖主路径、权限、并发与异常。
8. **安全合规**：敏感字段加密/脱敏；上传 MIME/大小/路径校验；限流；防重放。

## 3. 架构原则

1. **双面后端**：后台面 `/api/*`（camelCase、按需扩展）+ App 面 `/api/app/*`（snake_case、端专属 DTO），共享领域与应用服务。
2. **领域先行**：先补领域模型/端口，再写用例，最后接 HTTP；禁止 handler 直连 ent。
3. **状态机集中**：订单状态流转只允许经 `OrderAppService`，禁止任意 `UPDATE status`。
4. **服务端权威**：价格、库存、优惠、骑手收入全部服务端计算。
5. **幂等与并发**：下单幂等键、支付幂等、抢单单条条件更新、状态流转 `WHERE status=旧态`。
6. **事务边界在 application**：跨表一致性走 `TxRunner`。
7. **可回滚**：每个里程碑独立 migration（003、004…），先写 down 再写 up。
8. **支付可插拔**：`PaymentGateway` 接口，先 mock/余额，后微信/支付宝。
9. **金额精度**：过渡期沿用 float64 元并统一四舍五入到分；支付渠道接入前完成整数分迁移评估。
10. **不破坏联调**：新增字段只增不改；删除/改义必须走版本化契约。

## 5. 阶段计划

### M0 · 地基与账号（本轮）

**目标**：三端可以用正确角色登录并拿到自己的上下文；文件可上传；测试数据齐备。

| 交付 | 验收 |
|---|---|
| 短信登录建 credential；`/auth/refresh` 对无密码用户可用 | 短信登录 → me → orders → refresh → logout 全通 |
| `/api/app` 命名空间 + 角色守卫 + 主体绑定校验（1202/1203） | user 调 store 接口 403；merchant 调 client 接口 403 |
| `GET /api/app/client/me`、`PUT /me`、`GET /regions`、`PUT /region` | 新用户可选区域并回读 |
| `GET /api/app/store/me`、`GET /api/app/driver/me` | 返回店铺/骑手上下文与今日数据 |
| `POST /api/merchants/:id/account`、`POST /api/riders/:id/account` | 事务创建 user+credential+双向绑定；重复开通 409 |
| 上传 `POST /api/app/common/uploads` + `GET /uploads/*` | 图片上传返回 URL 并可访问；超限/类型错误有码 |
| seed：客户端/商家/骑手测试账号 | 三个账号可登录并联调 |
| 文档与测试 | `go build/vet` 通过；新增集成用例全绿 |

### M1 · 商品与门店

- 表：`dish_categories`、`dishes`、`user_addresses`；`merchants` 增经营设置列。
- 约束：`merchants.owner_user_id`、`riders.user_id` 加部分唯一索引（非空时唯一），防止并发重复开通账号。
- API：商家菜单 CRUD/上下架、营业设置、店铺状态；用户商家列表/详情/菜单、地址 CRUD/默认。
- 计价参数（打包费/配送费/起送价）落库并由服务端读取。
- 验收：用户端可浏览真实菜单并维护地址；商家端可改菜/改营业状态。

### M2 · 交易闭环

- 表：`orders` 生命周期字段、`order_events`、`payments`。
- API：用户下单/取消/支付/确认；商家接单/拒单/出餐；骑手抢单/取货/送达；三端订单列表/详情。
- 状态机：待支付 → 待接单 → 备餐中 → 待取货 → 配送中 → 已送达 → 待评价 → 已完成（旁路取消/售后/异常）。
- 验收：一条订单全链路跑通；并发抢单仅 1 成功；价格篡改被服务端纠正；重复下单幂等。

### M3 · 履约实时

- 表：`rider_locations`；Redis GEO。
- API：位置上报、`GET /app/client/orders/:id/track`。
- cron：待支付超时取消、待接单超时、自动确认收货、评价期结束、公告定时发布。
- 后台同步：订单状态筛选/配色补全新状态，详情 `steps` 切到 `order_events` 时间线。
- 验收：客户端追踪页真实移动；超时订单自动流转；轨迹/ETA 与订单状态一致。

### M4 · 资金与售后

- 表：`wallet_accounts`、`wallet_transactions`、`refunds`、`reviews`、`user_coupons`；`settlements/withdrawals` 主体化。
- API：商家/骑手收入与流水、提现申请；用户评价、退款售后；优惠券领取/核销。
- 验收：收入可追溯（订单 → 流水 → 余额）；提现按规则校验并进入审核；退款产生反向流水。

### M5 · 商用加固

- 真实支付（微信/支付宝）与回调验签、对账任务；风控规则（频次/金额/设备）；压测与容量；灰度与回滚演练；监控告警与 SLO；隐私合规与数据留存。
- 验收：支付成功率/对账差异可监控；压测达标；故障演练通过。

## 6. 数据演进策略

- 迁移目录递增：`003_app_surface`、`004_orders`、`005_wallet`…；每个含 `up`/`down`。
- 只增列/增表；改义列必须新增列 + 双写 + 回填 + 切读 + 删旧列（四步）。
- 历史数据回填脚本独立（`cmd/backfill`），可重入、可 dry-run。
- 生产禁止 `Schema.Create` 自动迁移（当前仅 dev 使用）。
- 金额迁移到整数分时，先新增 `*_cents` 列并双写，再切读，最后删旧列。

## 8. 发布与灰度

1. dev：本地容器 + `migrate up` + `seed`，三端 `10.0.2.2:8080`。
2. staging：独立库，跑全量集成 + 冒烟；数据脱敏。
3. prod：先执行 down 可用的迁移 → 灰度 1 个区域 → 观察下单/支付/抢单指标 → 全量。
4. 回滚：应用回滚 + 迁移 down（只回滚当次新增列/表）；资金类迁移禁止自动 down，需人工脚本。

## 9. 可观测与运维

- 指标：`app_order_created_total`、`app_order_paid_total`、`order_grab_conflict_total`、`delivery_duration_seconds`、`payment_success_rate`、`withdraw_pending_total`。
- 日志：统一 `request_id`，状态流转打印 `order_id from→to actor`。
- 告警：支付失败率、抢单冲突率、超时订单数、任务积压、5xx。
- 备份：PG 每日全量 + WAL；上传目录定期归档。
- 审计：资金/账号/审核/配置变更不可删除，保留 ≥ 180 天。

---

## 10. 安全与合规

- 手机号/身份证/银行卡：加密存储 + 列表脱敏；骑手抢单前不见完整号码。
- 上传：MIME 嗅探 + 大小限制 + 随机文件名 + 目录穿越防护；不执行上传内容。
- 限流：登录/短信/下单/抢单/提现分别限流。
- 防重放：幂等键 + 时间窗；支付回调验签。
- 权限：越权矩阵纳入集成测试；管理员操作二次确认（前端）。
- 隐私：用户可导出/删除个人数据（M5 评估）。

## 11. 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| 范围过大导致半成品 | 三端无法联调 | 严格按 M0→M5，每阶段可独立联调 |
| 状态机与后台中文枚举冲突 | 后台 UI 破坏 | 中文入库 + 英文 `status_code`，后台映射不变 |
| 金额 float 精度 | 对账差异 | 统一舍入；支付前迁移整数分 |
| 抢单并发 | 一单多骑手 | 单条条件 UPDATE + 唯一约束 + 并发测试 |
| 短信/支付第三方资质 | 上线阻塞 | 先 mock/余额；资质并行办理 |
| 单机 cron 重复执行 | 重复取消/结算 | 分布式锁（Redis）+ 幂等任务 |
| 迁移不可回滚 | 生产事故 | down 脚本 + staging 演练 |
