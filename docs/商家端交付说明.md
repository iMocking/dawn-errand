# 曙光跑腿商家端交付说明

> 交付范围：将 `design/store`（375×812「曙光商家」11 页设计稿）以 **Android 原生 Kotlin + MVVM** 还原为可运行应用，位于 `apps/store`。
> 本轮在已完成 11 页还原的基础上继续完善：修复 3 处 UI 缺陷；登录页新增「邮箱密码」真实后端登录；新增资质证照、结算账户、顾客评价、商家客服、设置 5 个页面；打通营业设置编辑、菜品新增/编辑、提现、订单处理等交互闭环；业务状态本地持久化。

## 4. 登录（双模式）

### 4.1 UI

`activity_login.xml` 表单卡片顶部新增「手机验证码 / 邮箱密码」双 Tab（选中橙色加粗 + 24×3dp 下划线），切换联动两组输入区。协议勾选、底部入驻引导保留。

### 4.2 手机验证码（演示模式）

- 后端 `/api/auth/sms/send`、`/api/auth/sms/login` 当前未部署（运行中的后端返回 404 / code 1401）。
- 演示规则：合法 11 位手机号 + 任意 6 位数字验证码登录；`获取验证码` 提示「演示环境请输入任意 6 位数字」。
- 会话保存为 `demo-token-<手机号>`，设置页账号标签显示「演示账号」。

### 4.3 邮箱密码（真实后端）

- `POST {API_BASE_URL}/api/auth/login`，请求体 `{"account":"<邮箱>","password":"<密码>"}`（字段名是 `account`，支持邮箱/手机号）。
- 成功：保存 `token`、用户名称、账号、角色到 `SharedPreferences("store_session")`；进入主页面。
- 失败：Toast 透传后端 `message`（如 401 账号或密码错误、403 未验证邮箱）。
- 网络异常：Toast「无法连接服务器，请检查网络后重试」。
- 网络请求在 `Dispatchers.IO` 执行（`LoginViewModel` + coroutines），请求中按钮显示「登录中…」并禁用。
- 密码框支持「显示/隐藏」切换。

## 5. 本轮新增/完善的功能

### 5.1 营业设置（全部可编辑 + 持久化）

`BusinessActivity` 中营业时间、起送价、配送范围、配送费、店铺公告、满减活动均可点击编辑（`AlertDialog` + 校验，非法输入保持弹窗并标红）；开启/歇业、自动接单开关即时生效并 Toast 提示。保存后写入 `SharedPreferences("store_settings")`，工作台店铺状态徽标、「已歇业」灰态横幅同步刷新。

### 5.2 菜品管理

- 新增/编辑菜品：名称、分类、售价、原价、库存、月售、描述、上架开关；保存写入 `DishStore` 并持久化到 `SharedPreferences("store_dishes")`。
- 分类 Tab 切换、上架开关切换即时刷新列表；重启应用后保留。
- 编辑已有菜品时可回填分类与描述；新增菜品自动分配占位图样式。

### 5.3 收入提现闭环

- 余额、近期收支记录来自 `FinanceStore`（`SharedPreferences("store_finance")`）。
- 提现弹窗：显示可提现余额、支持「全部提现」、校验最低 ¥1.00 与余额上限、展示 0.6% 手续费。
- 确认后扣减余额、顶部插入「提现到…」流水，Toast 展示扣除手续费后的预计到账金额；重启后余额/流水保留。
- 提现按钮文案跟随结算账户（微信钱包 / 银行尾号）。

### 5.4 结算账户

`SettlementActivity`：展示当前结算账户；微信钱包/银行卡二选一；银行卡支持绑定、更换、解绑（持卡人/开户银行/卡号校验，卡号脱敏展示），默认账户切换即时生效并持久化到 `SharedPreferences("store_settlement")`。

### 5.5 顾客评价

`ReviewsActivity`：4.8 分评分汇总 + 全部/好评/中评/差评筛选 + 评价列表（头像首字、星级、标签、商家回复）。商家可对评价「回复 / 修改回复」，回复写入共享状态并即时刷新。

### 5.6 商家客服

`SupportActivity`：商家服务热线 400-000-0000（整卡/呼叫按钮唤起系统拨号盘）、在线客服引导、4 条常见问题展开/收起（箭头旋转动画）、意见反馈。

### 5.7 设置

`SettingsActivity`：账号信息（店铺名/账号/角色标签）、新订单提醒/系统通知开关（持久化）、清除缓存（实时计算并清空 `cacheDir`）、语言、版本、隐私政策/用户协议入口、退出登录（确认弹窗 → 清会话 → 回登录页并清任务栈）。

### 5.8 资质证照

`QualificationActivity`：认证状态卡 + 营业执照 / 食品经营许可证 / 法人身份证（统一社会信用代码、身份证号脱敏），敏感字段脱敏展示。

### 5.9 订单详情增强

- 客服电话、联系顾客、联系骑手均使用 `ACTION_DIAL` 唤起系统拨号盘；演示数据中的掩码手机号无法直拨，统一回退到测试号码 `13800008888`（400 热线等真实号码原样拨打）。
- 配送中订单新增骑手信息卡（骑手姓名、状态、预计送达、联系骑手）；状态卡按待接单/制作中（橙）、配送中（蓝）、已完成（绿）切换配色。
- 底部「查看配送」定位到骑手卡；「接单 / 拒单 / 通知骑手取餐」仍走共享订单状态，工作台角标联动。

## 6. 数据与持久化

| SharedPreferences | 内容 |
|---|---|
| `store_session` | token、名称、账号、角色、手机号、是否真实后端登录 |
| `store_settings` | 营业开关、自动接单、营业时间、起送价、配送范围、配送费、公告、满减、通知开关 |
| `store_dishes` | 分类与菜品 JSON（新增/编辑/上下架结果） |
| `store_finance` | 可提现余额、收支流水 JSON |
| `store_settlement` | 结算账户类型、开户行、卡号、持卡人 |

业务数据初始值来自 `StoreRepository`（与 design 稿一致的演示数据）；`StoreApp` 在进程启动时初始化各 Store；状态变更通过 `LiveData` 驱动界面。

## 8. 已知限制与偏差

1. **业务数据仍为演示数据**：运行中的后端未提供商家端业务接口（店铺/菜品/订单/结算/评价等），这些页面使用 `StoreRepository` 演示数据 + 本地持久化；唯登录（邮箱密码）为真实后端链路。
2. **手机验证码为演示模式**：后端 `/api/auth/sms/*` 未部署（404），接入后可将 `LoginViewModel.loginDemo()` 替换为真实短信登录；目前任意 6 位验证码放行。
3. **商家账号角色**：测试账号 `store.owner@dawnerrand.local` 在后端为 `user` 角色（旧后端无 `POST /users/:id/role`），应用显示「商家账号」；正式环境应由平台开通 `merchant` 账号。
4. **Token 续期**：仅保存 access token，未实现 refresh 自动续期；access token TTL 900s，长时间停留后需重新登录（与后端当前配置一致）。
5. **图片上传未接入**：菜品图仍为占位图标，点击「上传图片」提示接口待接入。
6. **状态栏/导航栏为固定浅色方案**：登录/工作台/我的为橙色状态栏 + 白色图标，其余页面白色状态栏 + 深色图标；未做 Android 15 强制 edge-to-edge 的全面适配。
7. **页面扩展**：资质证照、结算账户、顾客评价、商家客服、设置为按设计规范新增的页面（设计稿仅 11 页），已在 `AndroidManifest.xml` 注册。
8. **演示电话**：订单/顾客手机号为掩码；`dial()` 对不足 11 位的号码回退到测试号码 `13800008888`，仅用于演示拨号盘唤起。

## 9. 后端契约速查

统一返回 `{code, message, body, request_id}`（`code=0` 成功）；鉴权 `Authorization: Bearer <token>`。

| 接口 | 方法 | 请求体 | 说明 |
|---|---|---|---|
| login | `POST /api/auth/login` | `{account, password}` | account 支持邮箱/手机号；成功 body `{token, refresh_token, user{id,name,avatar,role}, permissions}`；未验证邮箱 403 |
| sms_send | `POST /api/auth/sms/send` | `{phone}` | 运行中后端 404（未部署） |
| sms_login | `POST /api/auth/sms/login` | `{phone, code}` | 运行中后端 404（未部署） |
| register | `POST /api/auth/register` | `{email, password, name}` | 注册后需邮箱验证 |
| email_verify | `GET /api/auth/email/verify?token=` | — | 验证邮件中的 token |
| me | `GET /api/auth/me` | — | 登录态用户/权限（当前 App 未使用） |
| logout | `POST /api/auth/logout` | `{refresh_token}` | 当前 App 仅本地清会话，未调用服务端撤销 |
