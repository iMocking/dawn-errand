> 交付范围：将 `design\client`（375×812 移动端「曙光跑腿」乡镇跑腿 App，15 页设计稿）以 **Godot 4.7.2** 还原为可运行的桌面窗口客户端，位于 `apps\client`。架构为 **MVVM 数据驱动视图**，对接后端真实 API（`/api/auth/*`），支持「邮件/密码」与「手机号/验证码」两种登录。

## 3. MVVM 数据驱动架构

```
View（src/ui/screens/*/xxx_view.gd）
  │  build() 组装控件；bind() 通过 BindHub 订阅 VM 可观察属性
  ▼
BindHub（src/core/bind_hub.gd）——绑定/解绑生命周期，场景退出自动断开
  ▼
ViewModel（src/viewmodels/*_vm.gd，extends ViewModel）
  │  obs(name, initial) 可观察属性；list(name) 可观察列表；Command 封装动作
  ▼
Model（src/models/*.gd）+ Service（src/services/auth_service.gd）+ Api（autoload api_client.gd）
```

- **单向数据流**：用户输入 → View 调用 VM 方法（如 `vm.set_code(t)`）→ `set_prop` 触发 `changed` 信号 → BindHub 回调重绘。VM 不持有任何节点引用；View 不直接读 Model。
- **路由**：`App.open_screen/replace_screen/go_back`（navigator push/replace/pop）；`SCREENS` 注册表 + `create_vm` 工厂统一装配；Shell 四 Tab 懒加载。
- **会话**：`SessionModel` 持久化 `user://session.json`；`Api` 401 时**单飞刷新**（并发请求只发一次 refresh，成功后重放），refresh 失败才回登录页。
- **拆屏即释放**：`screen_base` 在 `_exit_tree` 时 `vm.dispose()` + BindHub 断开全部订阅，无悬挂引用。

## 4. 后端 API 对接

客户端 `src/services/auth_service.gd` 对接（真实 HTTP，非 mock）：

| 方法 | 端点 | 说明 |
|---|---|---|
| login_password | `POST /api/auth/login` | `{account, password}`，account 支持邮箱或手机号 |
| send_sms_code | `POST /api/auth/sms/send` | `{phone}`；dev 环境回显 `dev_code` |
| login_sms | `POST /api/auth/sms/login` | `{phone, code}`；未注册自动创建账号 |
| fetch_me | `GET /api/auth/me` | 登录态用户/权限 |
| logout | `POST /api/auth/logout` | `{refresh_token}`，后端升级会话版本全量失效 |
| refresh | `POST /api/auth/refresh` | `{refresh_token}`，轮换（SessionModel 单飞调用） |

统一返回 `{code, message, body, request_id}`（`code=0` 成功）；鉴权 `Authorization: Bearer <token>`。登录成功 `body` 为 `{token, refresh_token, user{id,name,avatar,role}, permissions}`——已与运行中后端实测对齐（注册成功、错误凭据 401、未验证邮箱 403、字段名一致）。

> ⚠️ **当前 8080 运行的是旧预编译后端**（缺 `/api/auth/sms/*`）。手机号验证码登录需在放行 Go 工具链后重新编译部署后端（见 `docs/后端交付报告.md` §7.5/§7.10）。期间可先用「邮箱/密码」登录（真实链路）或 dev 环境 `dev_code` 联调。

商家/订单/地址/优惠券等业务数据当前来自 `src/data/demo_data.gd`（后端暂无 C 端对应接口）；接口就绪后替换各 VM 中的 demo 调用即可，视图层零改动。
