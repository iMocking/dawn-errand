# 曙光跑腿 · 客户端（Android 原生 Kotlin）交付说明

> 版本：v1.2.1 ｜ 工程：`apps\client` ｜ 包名：`com.dawnerrand.client` ｜ 更新：2026-10-25
> 基准：375×812 设计稿像素级还原；模拟器 984×2132 / density 420
> 本轮：在原有 15 屏基础上补齐 **真实短信登录链路、本地数据持久化、订单闭环、地址/优惠券选择、7 个新页面**，并修复 10 余处 UI/交互缺陷。

---

## 1. 总览

客户端为 **Android 原生 Kotlin（View 体系，无 Compose）**，覆盖 `design\client` 的 15 个业务屏，并在本轮扩展 7 个功能页（商家入驻 / 成为骑手共用 1 个 Activity 的双模式），形成 **21 个 Activity + 4 个主 Tab Fragment**、21 个页面布局的完整用户端应用。

底部四 Tab 均为**内容页**：`MainActivity` 用 add/hide/show 管理 `HomeFragment / ErrandFragment / OrdersFragment / ProfileFragment`，点击「跑腿」「订单」不再跳转独立 Activity；`ErrandActivity / OrdersActivity` 仅保留为深链/兼容包装，内部同样复用对应 Fragment。

| 核心页（设计稿） | 扩展页（本轮新增） |
|---|---|
| Splash / Login / Home / Errand / Orders / Search / MerchantDetail / OrderConfirm / PaySuccess / OrderTrack / Review / Address / AddressEdit / Coupons / Profile | OrderDetail（订单详情）/ Settings（设置）/ ProfileEdit（个人资料）/ HelpCenter（帮助中心）/ CustomerService（联系客服）/ JoinActivity（商家入驻 / 成为骑手双模式）/ LegalActivity（用户协议 / 隐私政策） |

三端（client / driver / store）继续共用 `Design.kt` 设计令牌（主色 `#FF6B2C`、价格红、成功绿等）与 `Ext.kt` 系统栏适配。

## 4. 登录：真实短信链路 + 演示降级

### 4.1 真实链路

- `POST /api/auth/sms/send` `{phone}` → 成功返回 `{code:0, body:{dev_code?}}`；
- `POST /api/auth/sms/login` `{phone, code}` → `{token, refresh_token, user:{id,name,avatar,role}, permissions}`；
- 请求统一带 `X-Request-ID`，按 `{message, body, request_id, code}` 解析，`code != 0` 抛出 `ApiException`；
- dev 环境后端会回显 `dev_code`，客户端自动填入验证码并提示「开发环境已自动填充」；
- 登录成功后写入 `client_session`：`token / refresh_token / phone / name / user_id / demo`，昵称与手机号同步到本地资料。

### 4.2 演示降级

- 后端尚未部署短信接口（HTTP 404 / code 1401）或网络不可用时，自动切换 **演示模式**：任意 6 位验证码可登录，`demo=true`；
- 演示手机号 `13888888888` 对应种子用户「王建国」；其他手机号为「用户 + 后四位」；
- 登录页仍保留「用户协议 / 隐私政策」可点击阅读、「获取验证码」60s 倒计时、协议勾选校验；
- 微信 / 支付宝登录仍为设计稿占位（toast 提示）。

### 4.3 本机实测

| 场景 | 结果 |
|---|---|
| 最新后端（8090，源码编译版）短信发送 + 登录 | 发送成功、自动回填 `dev_code`；登录成功，`client_session` 中 `demo=false`、`user.name=用户8888` ✅ |
| 旧后端（8080，未部署短信接口） | 发送 404 → 自动降级演示模式 → 任意 6 位验证码登录，`demo=true` ✅ |
| 退出登录 | 清空 `client_session` 并清任务栈回到登录页 ✅ |
| 昵称修改 | 修改后同步 `client_session` 与本地快照，强制停止重开仍保留 ✅ |

## 5. 数据层（本轮重点）

### 5.1 组成

- `Models.kt`：`Merchant / Dish / CartItem / OrderLine / Order / Address / Coupon / UserProfile / ClientSettings / JoinApplication / Feedback`。
- `ClientJson.kt`：订单、地址、优惠券、购物车、设置、申请、反馈的 `org.json` 读写；不新增 Gson/Moshi 依赖。
- `DemoRepository.kt`：单对象本地仓库 + 种子数据 + 所有业务方法；首次启动写入种子，之后增删改全部持久化。
- `ClientApp.kt`：`Application` 启动时 `DemoRepository.init(this)`。

持久化位置：`SharedPreferences("client_demo")`（业务快照 JSON，key=`snapshot_v3`）+ `SharedPreferences("client_session")`（会话）。

### 5.2 已持久化的数据

| 数据 | 能力 |
|---|---|
| 用户资料 | 昵称、手机号、余额、积分、会员等级；昵称可编辑并持久化 |
| 地址 | 新增 / 编辑 / 删除 / 设为默认 / 默认地址回填；手机号掩码展示 |
| 购物车 | 按商家隔离、数量加减、清空；跨商家添加时二次确认清空 |
| 订单 | 新建、状态流转、取消、支付、确认收货、评价、申请售后、删除、再来一单；订单明细/费用/地址/备注/优惠券全部落盘 |
| 优惠券 | 可用 / 已使用 / 已过期；下单选择、门槛校验、抵扣、核销 |
| 搜索 | 最近搜索最多 8 条、删除单条、清空 |
| 设置 | 订单通知 / 优惠通知 / 声音提醒开关 |
| 入驻 | 商家 / 骑手申请状态与提交时间 |
| 反馈 | 客服页意见反馈本地留存 |

### 5.3 订单状态与操作

状态：`待支付 / 待接单 / 配送中 / 待评价 / 已完成 / 已取消 / 退款售后`。

| 状态 | 操作 |
|---|---|
| 待支付 | 取消订单、去支付 |
| 待接单 | 取消订单、查看配送 |
| 配送中 | 查看配送、确认收货 |
| 待评价 | 去评价、再来一单 |
| 已完成 | 再来一单；未评价可评价 |
| 已取消 | 删除订单、再来一单 |
| 退款售后 | 查看进度（详情） |

下单公式：`合计 = 商品小计 + 配送费 3.0 + 打包费 1.5 − 新用户立减 3.0 − 优惠券面额`。
订单提交后写入 `待接单`，清空购物车并核销优惠券；「再来一单」按订单明细回填购物车并跳转商家。

## 6. 页面与业务

### 6.1 设计稿 15 屏（保留 + 增强）

- **Splash**：渐变 + 星星 + logo + 版本；1.4s 按会话跳 Login / Main。
- **Login**：真实短信 / 演示降级、60s 倒计时、协议勾选与协议页、三方登录占位。
- **Home**：动态问候（按时段）、登录昵称、默认地址、搜索、双场景卡、推荐横滑、附近商家；「查看全部」进搜索；定位进地址。
- **Errand**：主页「跑腿」Tab 内容；4 类型 Tab（费用/提示/文案随类型切换）、取/收货地址（收货可选地址、取货可编辑、支持交换）、描述、费用预估、立即下单；提交生成跑腿订单并支付成功。
- **Orders**：主页「订单」Tab 内容；4 Tab + 数量角标、动态操作、点击卡片进详情、空状态、评价后状态回写；「我的」订单状态入口可直接切到对应过滤 Tab。
- **Search**：热门/历史（持久化）/清空；匹配商家名、标签、商品名；单结果直接进店，多结果显示商家卡。
- **MerchantDetail**：渐变 Hero + 热销角标 + 信息卡；动态分类筛选；每商家独立菜单；加购/减购数量控件；跨商家购物车冲突确认；长按购物车清空；去结算。
- **OrderConfirm**：选择地址（选择器）、商品明细、配送费/打包费/新用户立减、优惠券选择、备注、支付方式（微信/支付宝/余额）、提交防重。
- **PaySuccess**：金额、类型、订单号、真实送达地址；返回首页 / 查看配送。
- **OrderTrack**：按订单状态展示等待接单/取货中/已送达/已取消/售后；进度条与步骤联动；骑手卡按状态显隐；呼叫骑手（拨号盘）。
- **Review**：5 星 + 动态评分文案 + 6 标签（两行，多选）+ 文本 + 提交写回订单（已评价）。
- **Address**：3 地址、默认/标签、编辑、删除、设为默认；选择模式返回 `addressId`。
- **AddressEdit**：联系人/手机号/详细地址、单一标签、默认开关、删除、保存校验。
- **Coupons**：可用/已使用/已过期状态、面额/门槛/有效期、去使用、详情弹窗；选择模式返回 `couponId` + 「不使用优惠券」。
- **Profile**：动态昵称/手机号/默认地址、优惠券/余额/积分/等级、订单角标、地址/优惠券/入驻/客服/帮助/设置入口；点击头像进资料编辑。

### 6.2 本轮新增 7 页

- **OrderDetail**：状态卡、订单信息（编号/支付/地址/备注）、商品明细与费用、订单进度时间线、联系商家/客服、申请售后、底部动态操作。
- **Settings**：账号资料、3 个通知开关、清除缓存、关于、用户协议、隐私政策、帮助中心、客服、退出登录。
- **ProfileEdit**：头像预览、昵称编辑（2-12 字）、手机号只读、保存。
- **HelpCenter**：问题搜索、分类 chips、12 条 FAQ 展开收起、客服入口。
- **CustomerService**：在线客服入口、400 热线（系统拨号盘）、常见问题、意见反馈（本地留存）。
- **JoinActivity**：商家入驻 / 成为骑手双模式；差异化标题、说明、类型选项（餐饮/超市/水果/卤味/其他；电动车/摩托车/自行车/步行）；提交后展示「审核中」状态卡。
- **LegalActivity**：用户协议 / 隐私政策静态文本页（登录页与设置页共用）。

### 6.3 本轮修复的缺陷

- 订单列表新增订单使用不可变 `listOf().toMutableList().add()` 导致 **新订单不落库**；
- 首页「点个饭 / 跑个腿」两卡片的间距 margin 加在卡片外侧，中间无间隙；改为左卡右 margin + 右卡左 margin；
- 底部 Tab 图标：首页由房子换为饭碗、跑腿由小人换为小电动车，订单图标描边同步从 2.0 调为 1.8；四枚图标统一使用透明填充 + round cap 线框，与「我的」用户图标风格一致；
- 「我的」订单卡片图标与「待支付/待接单/配送中/待评价」文字错位：标签 TextView 未设置居中且默认撑满宽度，已改为 `Gravity.CENTER` + `MATCH_PARENT`；
- 「跑腿 / 订单」Tab 原本跳转独立 Activity，且独立页带返回箭头、没有底部 Tab；改为 Tab 内容 Fragment，保留底部导航与状态；首页「跑个腿」和「我的」订单入口也统一改为切 Tab；
- 订单 icon 资源 id 跨构建会漂移，改为恢复时按 `merchantId/type` 重新绑定；
- 订单详情确认收货后使用旧 `Order` 对象渲染，状态不刷新；
- 订单「进行中」Tab 选中态把实心橙色 drawable 当背景，白字被吞；
- 优惠券「去使用」按钮高度被 `MATCH_PARENT` 压成 0，重新布局到卡片右侧；
- 跑腿 Tab 文本未设置 wrap + 居中，首项贴边裁切；
- 评价标签单行排布被挤压换行，改为两行三列；
- 搜索热门 chips 溢出挤压，改为横向滚动；
- 商家 Hero 热销角标被信息卡遮挡；
- 确认订单地址两行导致箭头穿插，改为单行省略；
- 支付成功长地址把「送达地址」标签挤成竖排，改为值区权重 + 两行右对齐；
- 头像/昵称修改未同步会话，重启后被旧昵称覆盖；
- 购物车/地址/优惠券/设置等原先只在内存或静态列表，重启即丢。

## 8. 已知限制 / 未决

1. **后端 C 端业务接口仍未提供**：商家、菜品、订单、地址、优惠券、评价、入驻均为客户端本地演示数据；数据可持久化但不跨设备同步。
2. **8080 当前运行的是旧二进制**（无 `/api/auth/sms/*`）：默认 APK 会走演示降级；部署最新后端后无需改代码即可真实短信登录。
3. 登录后的业务请求未接入 access token 自动刷新；`refresh_token` 已落盘，后续接 C 端 API 时补 401 单飞刷新。
4. 支付为演示模拟（提交即成功），未接入微信/支付宝 SDK；微信/支付宝登录同为占位。
5. 商家入驻 / 骑手申请只写本地状态，未调用后端审核接口（管理端已有商家/骑手创建与审核）。
6. 实名认证、发票、消息中心等尚未提供 C 端入口。
7. 图片/头像上传未实现（默认图标）；商家菜品图仍为设计稿色块 + 矢量图标。
8. 评价、反馈仅本地留存；接入后端后需替换 `DemoRepository` 同名方法。
9. 中文 adb 自动化输入受限（`input text` 仅 ASCII），本轮交互验证使用种子中文数据 + ASCII 输入；真机人工验证无碍。

## 9. 扩展建议

- 后端提供 C 端接口后，新建 `ClientApi`（Retrofit/OkHttp 或现有 `ApiClient` 扩展），保持 `DemoRepository` 方法签名不变，内部改为网络调用即可，页面零改动。
- 订单状态建议改为服务端推送/轮询驱动；当前新订单固定为「待接单」，演示环境不做自动流转。
