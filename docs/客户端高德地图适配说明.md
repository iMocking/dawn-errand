> 项目根：`D:\code\github\dawn-errand`；工程：`apps/client`（Android 原生 Kotlin，包名 `com.dawnerrand.client`）。
> 目标：配送进度页接入高德地图服务，客户实时追踪外卖/跑腿配送进度；v1.2.1 按美团/饿了么追踪页重做浮层、路线、标记与相机行为。

## 2. 高德 Key 配置（必需，需在开放平台申请）

1. 注册高德开放平台：<https://lbs.amap.com>
2. 控制台 → 应用管理 → 创建应用 → 添加 Key，平台类型选 **Android**；
3. 填写以下绑定信息：
   - 安全码 SHA1（调试签名，可用 `keytool` 从 `%USERPROFILE%\.android\debug.keystore` 导出）：
     `94:EF:1B:BB:5F:51:D9:1C:8E:39:EF:21:D6:F4:B6:6B:61:FA:4E:20`
   - 包名：`com.dawnerrand.client`
4. 构建时注入 Key：

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
Set-Location "D:\code\github\dawn-errand\apps\client"
.\gradlew.bat assembleDebug -PamapKey=<你的Key>
```

> 未配置 Key 的表现：地图不渲染（logcat 输出 `INVALID_USER_KEY` / `errorCode 10001` 鉴权提示），页面其余功能（状态卡、进度、骑手卡、模拟移动）全部正常。
> 生产发布：必须用**正式签名 SHA1** 重新申请 Key 并在发布构建中注入。

## 4. 架构设计（MVVM 数据驱动）

数据流（单一数据源 `OrderTrackViewModel.uiState: StateFlow<OrderTrack?>`）：

```
                         OrderTrackViewModel.uiState
                        （StateFlow<OrderTrack?>）
   ┌──────────────┬───────────────┬───────────────┬──────────────┐
   ▼              ▼               ▼               ▼              ▼
状态卡          进度 4 步        骑手卡           地图            （空→提示并关闭）
标题/描述      已提交→到店     姓名/车辆/     取货点Marker
预计送达分钟    →配送中(已行驶  接单数据/      送达点Marker
剩余距离公里    x公里)→送达确认  联系/呼叫      骑手Marker+朝向
                                               路线Polyline
                                               相机跟随/回中
```

分层：

| 层 | 文件 | 职责 |
|---|---|---|
| 数据模型 | `data/track/TrackModels.kt` | `TrackPoint / TrackPhase / StepState / TrackStep / OrderTrack` |
| 数据源 | `data/track/TrackingRepository.kt` | `stateFor(order, progress)` 纯函数生成追踪状态；演示路线：浠水县镇中心 → 王家湾村（6 点乡道路线 + Chaikin 平滑，Haversine 里程/航向/ETA） |
| ViewModel | `ui/screens/ordertrack/OrderTrackViewModel.kt` | 配送中订单 42s 线性推进（100ms 刷新）模拟骑手移动；StateFlow 驱动 UI 与地图 |
| 视图 | `ui/screens/ordertrack/OrderTrackActivity.kt` | MapView 生命周期、气泡图钉/分层路线/骑手脉冲/相机跟随与回中 |
| 地图辅助 | `MapPins.kt` / `AmapLocationSource.kt` | 竞品风气泡图钉、骑手方向标位图工厂；定位数据源（v1.2.1 追踪页不再自动定位，避免抢相机） |

**v1.2.1 追踪行为**：
- 演示进度由每 2s 跳 0.04 改为 **42s 线性推进、100ms 更新**，骑手沿 Chaikin 平滑路线连续移动；
- **高德驾车路径规划**（`RouteSearch`）优先替换演示路线，使路线贴合真实道路；搜索失败（Key 未开通搜索权限/无网络）自动回退本地乡道路线；
- 相机首载全路线取景（`moveCamera` 保证 Map 引擎延迟初始化时也生效），配送中按 1s 节流跟随骑手；用户拖动地图暂停跟随，右下角目标按钮一键回中；
- 状态卡、横向 4 步进度、骑手卡全部由 StateFlow 驱动；新订单配送中约 42s 后自动显示「骑手即将送达」。


**后端替换点**：追踪接口就绪后仅需把 `TrackingRepository.stateFor` 换成 `GET /orders/:id/track`（或 WebSocket 推送）的解析，ViewModel 与 UI 零改动（沿用 v1.1.0 的 DemoRepository 替换约定）。

## 5. 配送进度页实现要点（v1.2.1）

- **MapView 生命周期**：与 Activity 严格绑定 `onCreate/onResume/onPause/onDestroy/onSaveInstanceState`。
- **全屏地图**：`WindowCompat.setDecorFitsSystemWindows(false)`；顶部深色渐隐 + 浮层状态卡；底部圆角骑手卡。
- **浮层状态卡**：18sp 状态标题 + 「约 X 分钟」橙色胶囊 + 描述 + 三列指标（分钟送达 / 剩余公里 / 预计送达时刻）。
- **底部骑手卡**：拖拽把手视觉、骑手头像/姓名/接单数据、聊天/呼叫圆钮、横向 4 步进度（已接单/已取餐/配送中/已送达），进度线随 `stepProgress` 增长。
- **标记**：竞品风气泡图钉「商家」橙色 + 白色餐盒、「送达点」绿色 + 白色房子（尖角指向坐标，anchor 0.94）；骑手为橙色圆标 + 白色电动车 + 圆内方向箭头，随 `rotateAngle` 旋转，并叠加橙色脉冲 `Circle`。
- **路线**：白色 9dp 外框 + 灰色 7dp 剩余路线 + 橙色 7dp 已走路线，三层 Polyline 随进度实时分层；路线点按 Chaikin 平滑，避免硬折角。
- **相机**：首载 `moveCamera(newLatLngBounds)` 覆盖取货-送达；配送中 `CameraPosition(rider, 16.4f, 30f, 0)` 每秒节流跟随；用户拖动地图后 `followingRider=false`，右下角 `ic_my_location` 按钮回中并恢复跟随。
- **无定位干扰**：追踪页不再自动启用「我的位置」，避免系统定位把相机拉到用户位置、离开订单路线（定位权限与 `AmapLocationSource` 保留给后续场景）。
- **ETA / 距离**：按平滑路线里程与骑手平均 20 km/h 估时；预计送达时刻按当前时间 + 剩余分钟动态计算。

## 8. 已知限制

1. 高德 Key 未配置时地图瓦片不渲染（构建注入 `-PamapKey` 后生效）；v1.2.1 的浮层、状态与地图无关逻辑仍可用。
2. 3D 地图 SDK 仅支持 arm64-v8a / armeabi-v7a；x86 设备不可用（模拟器经转译运行，性能低于真机）。
3. 骑手位置为**演示模拟**（42s 走完全程）；后端追踪接口就绪后需替换数据源。
4. `RouteSearch` 需要 Key 开通路径规划/搜索权限；未开通时回退到本地浠水县乡道路线（不阻断追踪）。
5. 追踪页为避免相机被系统定位拉走，默认不开启「我的位置」；后续如需增加，建议只画蓝点、不移动订单相机。
6. 隐私默认「已同意」仅适用于演示环境；上线必须接入用户确认流程后再调用合规接口。
