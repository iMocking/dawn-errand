# 商用运维手册（M5）

> 适用：`dawn-errand` 后端（Go + PostgreSQL + Redis + 本地存储）
> 目标：把「可运行」提升到「可运维、可对账、可回滚、可告警」。

---

## 1. 部署拓扑

```
Nginx / 负载均衡（HTTPS）
        │
        ├── Go 服务 :8080（可多实例，后台任务用 Redis 锁选主）
        ├── PostgreSQL 16（主库 + 每日备份 + WAL）
        ├── Redis 7（会话/限流/验证码/分布式锁/GEO）
        └── 本地存储目录（或 OSS，通过配置切换）
```

启动顺序：PostgreSQL/Redis → `migrate up` → `seed`（仅首次）→ `server`。

---

## 2. 环境变量与密钥

| 变量 | 说明 | 生产要求 |
|---|---|---|
| `APP_ENV` | dev/test/prod | `prod` 关闭 dev 能力与宽松日志 |
| `JWT_SECRET` | JWT 签名 | ≥32 字节随机，定期轮换 |
| `CONFIG_ENCRYPTION_KEY` | 配置敏感值 AES-GCM | 独立密钥，禁止入库 |
| `BOOTSTRAP_TOKEN` | 初始化令牌 | 首次后立即更换 |
| `POSTGRES_DSN` / `REDIS_*` | 连接 | 专用账号、最小权限、TLS |
| `PAYMENT_CALLBACK_SECRET` | 支付回调 HMAC | 渠道独立密钥，按渠道轮换 |
| `ORDER_PAY_TIMEOUT_SEC` | 待支付超时 | 默认 900 |
| `ORDER_AUTO_CONFIRM_SEC` | 自动确认 | 默认 86400 |
| `STORAGE_*` | 上传 | 生产建议 OSS + CDN，限制 MIME/大小 |

密钥禁止写入仓库；使用密钥管理系统或容器 Secret 注入。

---

## 3. 数据库迁移与回滚

```powershell
go run ./cmd/migrate up      # 按版本执行 001..00N
go run ./cmd/migrate down    # 逆序回滚，每次只回滚一个版本
```

- 生产禁止 `cmd/server` 的 ent 自动迁移（仅 dev 使用）。
- 每次发布前在 staging 演练 `up → 验证 → down → 再 up`。
- 资金类表（wallet/refund/payment）禁止自动 down；回滚需人工脚本 + 备份。
- 迁移脚本必须幂等（`IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`）。

---

## 4. 备份与恢复

- PostgreSQL：每日全量 `pg_dump` + WAL 归档；保留 ≥30 天，异地一份。
- Redis：AOF（everysec）；仅缓存/会话可丢，锁与验证码可重建。
- 上传目录：每日增量归档；OSS 开启版本控制。
- 恢复演练：每季度一次，校验 `schema_migrations`、订单/钱包/支付对账差异为 0。

## 5. 监控与告警

关键指标（`/metrics`）：

| 指标 | 告警建议 |
|---|---|
| `dawn_http_requests_total{status=5xx}` | 5 分钟错误率 >1% |
| `dawn_http_request_duration_seconds` | P95 > 1s |
| `dawn_orders_timed_out_total` | 突增 3 倍 |
| `dawn_orders_auto_confirmed_total` | 突增 3 倍 |
| `dawn_location_reports_total` | 骤降（骑手端异常） |
| `dawn_track_requests_total` | 骤降/骤增 |
| `dawn_job_runs_total{result}` | 任务连续未执行 |

日志：JSON（zap），必须包含 `request_id`；订单状态变更记录 `order_id from→to actor`。
链路：`X-Request-ID` 贯穿 App → 网关 → 服务；排障先按 request_id 检索。

## 6. 支付回调与对账

### 6.1 回调

`POST /api/payments/callback/:channel`，统一报文：

```json
{ "order_id":"...", "trade_no":"...", "amount":29.00, "status":"paid", "timestamp":1792910000, "sign":"hex" }
```

签名：`HMAC-SHA256(secret, order_id|trade_no|amount(2位)|status|timestamp)`；时间窗 ±5 分钟；重复回调幂等。
真实微信/支付宝适配层：验签渠道报文 → 转换成本报文 → 调本接口（渠道密钥只存在适配层）。

### 6.2 对账

`GET /api/finance/reconciliation?date=YYYY-MM-DD`（`finance:view`）：

- `paid.orders` / `paid.amount`：当日支付单对应订单应付合计；
- `payment.count` / `payment.amount`：当日支付单合计；
- `refund.count` / `refund.amount`：当日退款合计；
- `diff` 必须为 0；`missing_orders` 必须为 0。

差异处置：先查 `payments` 与 `orders.payment_status`，再查渠道账单；差额挂账并人工复核，禁止直接改余额。

## 7. 发布与回滚

1. 构建镜像（固定 Go 版本），跑 `gofmt/go vet/go build` + 集成测试。
2. staging：迁移 + 冒烟（登录→下单→支付→接单→取送→确认→评价/售后）。
3. 生产：先迁移（可 down）→ 灰度 1 个区域 → 观察 30 分钟指标 → 全量。
4. 回滚：应用回滚到上一镜像；迁移按版本 down；资金数据只前滚不后滚。
5. 每次发布记录：版本、迁移版本、配置变更、回滚点。

---

## 8. 安全清单

- 全站 HTTPS；JWT/刷新令牌仅走 Header/Body，不落 URL。
- 上传：MIME 嗅探 + 扩展名由 MIME 决定 + 大小限制 + 目录穿越防护。
- 限流：登录/短信/下单/回调/提现分别限流（Redis）。
- 敏感数据：身份证/银行卡加密；列表脱敏；日志禁止打印明文。
- 权限：App 三端角色 + 主体绑定 + `tenant.Scope`；越权矩阵纳入集成测试。
- 审计：登录/改密/审核/提现/退款/配置变更不可删除，保留 ≥180 天。
- 依赖：定期 `govulncheck`，升级 ent/gin/pgx/redis 客户端。

## 9. 常见故障处置

| 现象 | 排查 | 处置 |
|---|---|---|
| 登录后 401/1006 | credential 是否存在、session_version | 补凭证/重新登录 |
| 登录 500（panic AuditLogCreate.defaults） | `ent/runtime.go` 是否被加上 `//go:build tools` | 移除构建标签并重新构建（ent 生成后自检） |
| 下单 500 | 库存/优惠券事务、迁移是否执行 | 查日志 request_id，回滚事务 |
| 抢单冲突 | 是否已被抢（1801） | 正常业务提示 |
| 回调验签失败 | secret/时间窗/金额格式 | 核对渠道配置，禁止跳过验签 |
| 对账有差异 | 支付单 vs 订单 | 挂账人工复核，不直接改余额 |
| 定时任务不执行 | Redis 锁残留/任务日志 | 删除过期锁，检查 runner |
| 上传 404 | 存储根目录/静态挂载 | 检查 `STORAGE_ROOT_DIR` 与挂载 |
